========================================
湾流签约助手 · 软件说明（精简版）
========================================
更新: 2026-06-04   入口程序: app.py


一、软件是做什么的（功能概览）
----------------------------------------
• 家庭医生签约自动化工具，目标是把"签约 → 确认 → 已签约"整条流程尽量自动化。
• 公卫3.0系统：真实接口登录（含国密 SM4/SM3 加密、二维码 2FA 扫码）、查询居民、
  批量发起家庭医生签约。
• 健康卡平台：连接平台、查询签约信息、对"待确认"合同做居民侧确认（editqr），
  这是真正能落到"已签约"的关键一步。
• 年龄绕行：对 18–60 岁需人脸的居民，临时修改档案出生信息绕开人脸验证，
  事务结束后"始终自动恢复"原身份证信息（带可行性预检 + 审计日志）。
• 自动绑卡（免人脸人群）：对 <18 / >=60 岁居民，捕获到一次微信 Wechatcode 后，
  可一键完成"绑卡 → 签约 → 确认"。
• 流量抓包：内置代理，自动捕获 OpenID 与 Wechatcode，供后续自动化复用。
• 结果记录：每条签约成功/失败都写入 Excel 日志（logs/成功、logs/失败 目录）。

【诚实声明 · 重要】
• "高级分析工具""安全评估"两类模块只是模拟/文档，不联网、不采集真实数据，
  请勿对外宣称"实时分析"或"实时渗透测试"。
• 唯一无法纯自动的步骤：需要在微信里打开一次"我的健康卡"页面，让代理抓到
  一个真实 Wechatcode（微信凭据无法伪造）。之后整批免人脸人群可全自动。
• "仅靠重提交档案把医生发起的签约推进到已签约"经生产实测【不成立】，
  到达"已签约"靠的是健康卡平台的居民侧确认链路。


二、怎么用（操作步骤）
----------------------------------------
启动:
1. 准备 Python 环境，安装依赖：requests、gmssl、cryptography、pycryptodome、Pillow。
2. 运行：python app.py（会打开图形界面）。

界面共 6 个标签页：
• [3.0系统签约]  — 登录公卫3.0、查询居民、批量发起签约。
• [健康卡确认]   — 连接健康卡平台、年龄绕行、对待确认合同做确认。
• [获取OpenID]   — 获取/管理 OpenID。
• [流量抓包]     — 开启代理，自动捕获 OpenID / Wechatcode / 签约请求模板。
• [状态取证]     — 只读取证：签约前/后各打一次快照，生成对比日志发回分析。
• [许可证配置]   — 账号与许可证设置。

状态取证（看清"已生效数据"怎么产生的，全程只读）:
1. 先在 [获取OpenID] 抓到户主 OpenID。
2. 到 [状态取证]，点"↙ 用健康卡页OpenID"带入，或手动粘贴。
3. ① 点【签约前快照】→ ② 去微信绑卡/让这几个人签约 → ③ 点【签约后快照】。
4. 点【生成对比日志】→ 日志保存在 logs/状态取证/ 下，把该文件发回给我们分析。
   （重点看带 ★状态 的行：CONTRACT_STATES/qyzfbs 由 1→6→0 即"已生效"的来源。）

常规签约流程:
1. 在 [3.0系统签约] 输入账号密码登录 → 按提示用手机扫二维码完成 2FA。
2. 查询/导入需要签约的居民名单。
3. 点击开始签约，发起家庭医生签约（公卫端会落库为"医生申请"状态）。
4. 如需真正到"已签约"：切到 [健康卡确认]，连接平台，对目标居民的待确认
   合同做确认（editqr）。

年龄绕行（18–60 岁需人脸的居民）:
1. 在 [健康卡确认] 展开"年龄绕行"区。
2. 先点 [🔍 可行性预检 (导出Excel)] 只读探测，确认哪些居民可绕行。
3. 勾选"启用年龄绕行"后执行；流程结束会自动恢复原身份证号。

自动绑卡（<18 / >=60 免人脸人群）:
1. 在 [流量抓包] 开启代理，在微信打开一次"我的健康卡"页 → 自动抓到 Wechatcode。
2. 之后对免人脸居民执行绑卡，一个 Wechatcode 可绑一批（每个 openid 最多 9 张）。
3. 绑卡后工具自动完成：绕过人脸 → 查询 → 建合同 → 确认。


三、怎么测试（验证可用性）
----------------------------------------
本地测试（不碰生产数据，安全）:
• 测试脚本集中在 .dbg/ 目录，用项目内 .venv 运行。
• 关键回归套件（共 231+ 项，应全绿）：
  - finalize_unit / finalize_functional / finalize_adversarial（档案推进状态机）
  - direct_sign_unit / direct_sign_functional（直签模板）
  - ph3_flow_functional（仿真 ggws，真 SM4 加解密跑全流程）
  - hc_api_functional（健康卡四个接口的功能 + 对抗测试）
  - qr_login_unit / age_bypass_unit / silent_failure_probe
  - bind_then_sign_unit_test（自动绑卡：年龄门槛/缺码/坏证/绑卡失败/全程成功）
• 运行示例：在 gulfsign-desktop 目录执行
  PYTHONUNBUFFERED=1 .venv/bin/python .dbg/<测试文件>.py

生产联机验证（需真账号 + 真人扫码，务必小批量）:
• 先用 1 条真实数据走通"登录 → 查询 → 发起 → 确认"，确认无误再放量。
• 验证脚本会全程自动清理实验合同，不在生产留痕。
• 健康卡确认链路已联机复核：连通、Token 有效、卡列表与状态可读。


四、排查问题（Troubleshooting）
----------------------------------------
• 启动报 "No module named 'gmssl'"：依赖未装或用错环境。
  → 激活正确的 .venv，pip 安装 gmssl 等依赖后再运行。

• 连接不上系统 / 登录失败：
  → 检查账号密码是否正确、是否过期（曾出现"密码错误"= 凭据过期）。
  → 登录后必须用手机扫二维码完成 2FA，未扫码会停在待确认，不会发起签约。

• 扫码后仍提示未认证：
  → 等待二维码轮询完成；网络不稳可重试。会话未达"完全认证"时工具会拒绝发起，
    这是防止半成品状态签约的保护，不是 bug。

• 发起成功但状态还是"医生申请"：
  → 这是正常的。公卫端医生发起只能到"医生申请"，要到"已签约"必须走
    [健康卡确认] 的居民侧确认（editqr）。

• 确认/绑卡提示"微信身份码不存在"：
  → Wechatcode 无效或未捕获。需在 [流量抓包] 开代理，在微信重新打开健康卡页出码。

• 年龄绕行被拒（"已实名认证的对象身份证号码不允许修改"）：
  → 该居民已实名/已面访，服务端硬性拒绝，属预期；预检会提前标出并跳过。

• 自动绑卡对 18–60 岁报拒绝：
  → 这类人群绑卡必须过腾讯人脸（无法伪造）。需人工绑卡或先年龄绕行后人工绑。

• 看不到结果 / 想查日志：
  → 用文件管理器打开 logs/ 目录，成功在 logs/成功，失败在 logs/失败，按日期分文件夹。
  → 年龄绕行审计在 logs/年龄绕行（身份证已脱敏，仅留后4位）。

• 脚本输出不实时刷新：
  → 运行时加 PYTHONUNBUFFERED=1 强制行缓冲。

• 运行目录报"找不到文件"：
  → 确认在 gulfsign-desktop 目录下运行；必要时先 cd 到该目录再执行。


五、一句话总结
----------------------------------------
登录扫码 → 发起签约 → 健康卡侧确认，即可到"已签约"；唯一手工步骤是
在微信出一次 Wechatcode，之后免人脸人群可全自动绑卡+签约。所有结果都有
Excel 留痕，遇到"自称成功"的情况工具会诚实改判为失败，绝不静默误报。
